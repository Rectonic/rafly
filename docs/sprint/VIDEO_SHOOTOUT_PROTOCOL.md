# Протокол сравнения видео на 100 SKU

## Решение, которое принимает тест

Тест отвечает на один вопрос, сокращает ли один видео-проход суммарное время до проверенного черновика каталога по сравнению с одним проходом штрихкодом или вручную. Видео не считается истиной об остатке и не получает права менять данные без ревью.

## Ворота эксперимента

Видео остаётся кандидатом на ускорение онбординга, только если одновременно выполнены все условия:

- в одном из двух магазинов видео быстрее базового способа минимум на 25 процентов по суммарному времени
- во втором магазине видео не медленнее базового способа
- в обоих магазинах ноль молча принятых неверных склеек
- для каждого метода получен проверенный черновик ровно по 100 SKU

Если хотя бы одно условие не выполнено, ворота не пройдены.

## Что считается проверенным черновиком

Для каждого из 100 SKU записаны источник, каноническое название, объём или вес, категория, штрихкод при наличии и статус проверки. Ревьюер подтвердил идентичность каждой позиции. Неоднозначные товары остаются отдельными строками с пометкой на проверку. Черновик с молча объединёнными товарами не считается проверенным.

## Участники и роли

- Владелец или менеджер разрешает тест и выбранные полки.
- Оператор видео делает один непрерывный проход по согласованному маршруту.
- Оператор базового способа делает один проход со сканером штрихкодов или ручным вводом.
- Ревьюер проверяет оба черновика по одному эталону и не видит итоговое время до завершения проверки.
- Хронометрист фиксирует границы этапов, устройство, сбои и паузы.
- Один человек может совмещать роли только если это записано до старта и одинаково для обоих методов.

## Подготовка в двух магазинах

- [ ] Выбрать два реальных магазина с разной плотностью полок.
- [ ] В каждом магазине зафиксировать ровно 100 SKU и маршрут полки.
- [ ] Получить согласие на съёмку выбранных полок только для каталога.
- [ ] Убедиться, что люди и кассовая зона не попадают в кадр.
- [ ] Подготовить закрытый эталон из фактических этикеток и вариантов упаковки для ревьюера.
- [ ] Дать обоим методам одинаковый исходный каталог, если он существует.
- [ ] Очистить черновик перед каждым проходом. Результат первого метода нельзя переносить во второй.
- [ ] В магазине 1 начать с видео, в магазине 2 начать с базового способа, чтобы снизить эффект обучения.
- [ ] Использовать один и тот же критерий идентичности и одну схему исправлений.
- [ ] Записать модель телефона, камеру, сканер, версию приложения и качество связи.

Если магазин не разрешает безопасную съёмку без людей, его заменяют до старта. Нельзя ослаблять правило приватности ради замера.

## Проход видео

### Начало времени

Хронометрист запускает таймер, когда оператор подходит к первой согласованной полке и начинает запись.

### Порядок

1. Оператор делает один проход по маршруту без повторной съёмки отдельных товаров.
2. Видео преобразуется в черновые наблюдения и кандидатов идентичности.
3. Ревьюер проверяет каждый кандидат, разделяет неверные склейки, добавляет пропуски и оставляет неоднозначные строки открытыми.
4. Ревьюер подтверждает готовность черновика по всем 100 SKU.

### Конец времени

Таймер останавливается только после подтверждения ревьюера. Обработка, ожидание, ревью и исправления входят в суммарное время.

## Проход штрихкодом или вручную

### Начало времени

Хронометрист запускает таймер, когда оператор подходит к первой согласованной полке и начинает сканирование или ручной ввод.

### Порядок

1. Оператор проходит тот же маршрут один раз.
2. Для товара со штрихкодом оператор сканирует код. Если кода нет или он неоднозначен, оператор вводит данные вручную.
3. Ревьюер проверяет каждый кандидат по тому же эталону, исправляет ошибки и оставляет неоднозначные строки открытыми.
4. Ревьюер подтверждает готовность черновика по всем 100 SKU.

### Конец времени

Таймер останавливается только после подтверждения ревьюера. Ручные исправления и ревью входят в суммарное время.

## Что измеряем

Время записывается в секундах отдельно по этапам:

- сбор на полке
- обработка до появления полного черновика
- ревью и исправления
- вынужденные технические паузы
- суммарное время до проверенного черновика

Техническая пауза не вычитается. В примечании указывается её причина. Обычный перерыв магазина, который одинаково остановил бы оба метода, записывается отдельно и требует решения до анализа.

## Расчёт ворот

Для каждого магазина:

```text
ускорение видео, % = (время базового способа - время видео) / время базового способа × 100
```

| Проверка | Требование | Факт | Пройдено |
| --- | --- | --- | --- |
| Магазин с выигрышем | Ускорение видео не меньше 25 процентов |  | да или нет |
| Второй магазин | Время видео не больше времени базового способа |  | да или нет |
| Качество магазина 1 | Ноль молча принятых неверных склеек |  | да или нет |
| Качество магазина 2 | Ноль молча принятых неверных склеек |  | да или нет |
| Полнота | Два проверенных черновика по 100 SKU в каждом магазине |  | да или нет |

Итог принимает владелец эксперимента после проверки исходных таблиц, а не по впечатлению от скорости записи.

## Отдельное checkout-исследование

Checkout не входит в сравнение каталогизации и не влияет на его время. Это отдельный изолированный Wizard of Oz тест. Он не доказывает продажу, оплату или фискальное событие.

### Скоуп

- [ ] Получить отдельное разрешение магазина на постановочные события.
- [ ] Использовать тестовую полку и тестовые идентификаторы, не затрагивающие живой остаток и фискальную систему.
- [ ] Подготовить 30 событий до старта и перемешать их порядок.
- [ ] Включить 10 постановочных изъятий, 10 сценариев взял и вернул, 10 событий без разрешённого движения, включая окклюзию и движение рядом с полкой.
- [ ] Для каждого события записать видео, ожидаемый исход, предложенное системой действие, решение ревьюера и применённое движение.
- [ ] Измерять ревью от появления карточки кандидата до решения утвердить, исправить или отклонить.
- [ ] Любое применение движения требует решения уполномоченного менеджера.

### Ворота checkout-исследования

- ноль несанкционированных движений
- ноль применённых движений в сценариях взял и вернул
- медиана времени ревью не больше 20 секунд
- ни одно событие не называется продажей без POS-доказательства

Медиана считается по всем 30 значениям после сортировки. Для чётного числа наблюдений берётся среднее 15-го и 16-го значения.

## Правило остановки

Видео убирается из продуктового роадмапа, если оно не проходит ворота сравнения, если его суммарное время не лучше штрихкода и ручного пересчёта, или если ревью checkout-событий дороже трёхминутного ежедневного закрытия. Checkout-исследование останавливается сразу при первом несанкционированном движении или первом применённом движении на сценарии взял и вернул. Модель не расширяют и не тренируют дольше вместо честной остановки ставки.
